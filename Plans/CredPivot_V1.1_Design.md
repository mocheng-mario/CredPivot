# 01. 产品愿景、边界与设计原则

## 1.1 产品定义

CredPivot 是一个**离线优先、本地拥有、加密存储、开放可恢复**的统一凭据管理器，面向希望同时管理网站账号、MFA 验证材料、SSH 密钥及开发者秘密的个人用户和开发者。默认不要求创建 CredPivot 云账户，也不要求运行自建 CredPivot 服务端。

统一入口不是把三个功能放到三个独立菜单中，而是通过一个 *Account / Item* 聚合实体，将同一服务的登录密码、TOTP、SSH Key、备用恢复码、服务器等建立可追踪的关系。例如 GitHub 工作账号在网页登录时推荐密码及 TOTP，在终端 SSH 操作时使用与该账号关联的密钥。

## 1.2 目标

- 首发同时交付 M 系列 Mac 应用与配套 Mac Chrome 扩展；无网络也能保存、查找、填充、生成 TOTP 和完成 SSH 授权。
- 本地工作库采用 SQLCipher；完整备份使用平台无关的 OVB 加密逻辑快照，不将实时数据库文件定义为交换或同步协议。
- 一个主密码解锁 Vault，提供独立高熵恢复密钥及 Mac Touch ID/Keychain 快捷解锁。
- 浏览器扩展依赖本机应用与 Agent，不持有独立保险库；主窗口关闭后仍可通过 Agent 按授权工作。
- 优先支持从 Bitwarden 迁入，导入前预览支持范围，导入后核对结果，不静默丢失内容。
- 首发提供自动本地恢复点、手动完整加密归档和独立恢复 CLI；恢复不依赖原设备、生物识别或在线服务。
- 数据格式与核心逻辑为 Android 和后续端到端加密同步保留兼容及升级路径，当前不实现网络同步。
- UI 优先做好 Mac 的键盘、窗口、授权与 Chrome 联动体验。

## 1.3 非目标（V1 不做）

- Android、Intel Mac、Windows/iOS、WebDAV 或其他网络同步、多设备冲突合并、设备配对和远端管理。
- Safari/Firefox/Edge 专门适配、Chrome CSV、Passkey、附件、内置 Git、通用字段级合并及多用户权限隔离。

- CredPivot 中心账号体系、厂商托管密钥或服务端代用户解密。
- Git Pull/Merge 双向数据同步；多个云后端同时可写的多主同步。
- 团队共享保险库、企业后台、组织级策略下发、紧急访问授权。
- 允许浏览器扩展脱离本地 App 自建加密数据库或独立同步。
- 声称能够绝对防御弱主密码的离线暴力猜测、已完全控制用户设备的恶意软件或历史备份中的旧秘密泄露。

## 1.4 设计原则

1. **数据所有权**：用户拥有完整加密文件；迁移不依赖厂商在线服务。
2. **默认最小权限**：页面、插件、SSH Agent、移动系统填充只取得完成当前操作所需的秘密。
3. **安全与可用性同等可验证**：本地保存成功、备份生成、备份恢复验证是不同的状态；首发不显示同步成功。
4. **不静默丢失数据**：过期编辑、重复导入和备份恢复不能直接覆盖现有内容；后续多设备冲突须保留完整候选。
5. **协议先于实现**：SQLCipher Schema、UI 和云供应商 API 不应反向定义开放 Vault 格式。
6. **拒绝自制密码学原语**：采用成熟的标准算法和库，只定义必要的文件封装与版本协议。

# 03. 产品范围、用户画像与优先级

## 3.1 目标用户

“第一类用户”指优先服务的用户群体，不是权限等级。首批目标为使用 M 系列 Mac、Chrome 和 SSH 开发工具，当前把凭据保存在 Bitwarden 的个人开发者。先解决本机账号、TOTP、SSH 的统一管理及可靠恢复，后续扩展到 Android 和自主云同步。

## 3.2 首发 P0 能力

| 域 | P0 范围 |
|:--|:--|
| Vault | 初始化、主密码、恢复密钥、锁定、Touch ID、本地目录迁移、安全重建 |
| 密码 | 增删改查、生成、站点匹配、已启用/待启用状态、10 条历史、可关闭检查提醒 |
| MFA | TOTP 二维码/URI/手动导入、账号关联、网站备用恢复码 |
| SSH | Ed25519 创建、导入导出，Mac Agent 按次或会话授权 |
| 迁入 | Bitwarden 普通 JSON 与密码保护加密 JSON；字段映射、预览、重复检测和结果报告 |
| 备份与恢复 | 自动本地恢复点、手动完整 OVB 归档、GUI 恢复与独立 Mac CLI |
| 客户端 | M 系列 Mac 应用与 Mac Chrome 扩展同时交付 |
| 体验 | 中文/英文、深浅色、搜索、键盘操作、核心无障碍、本地保存与备份独立反馈 |

## 3.3 后续阶段

1. **Android**：复用业务模型、加密格式和 Rust 核心，另外实现平台解锁及系统填充；系统下限在实施时重新确认，Android 14/API 34 仅保留为候选基线。
2. **同步**：以坚果云 WebDAV 为首个实测对象，验证通过后实现设备接入、增量、冲突、控制配置更新及恢复对账。Android 与同步可以分别开发，不把任一能力隐含为首发前置。
3. **其他扩展**：Chrome CSV、其他浏览器、Git 单向备份、RSA/ECDSA、Passkey、HOTP、CXF/KDBX、附件及其他云服务。Intel Mac 仅作需求观察，不承诺后续必定支持。
4. **远期评估**：Windows/iOS、团队共享、紧急访问、跨后端多主和多用户权限。

## 3.4 首发价值与边界验收

1. 从 Bitwarden 导入，查看映射、跳过项与重复项；已有本地修改不被静默覆盖。
2. Mac Chrome 保存与填充登录，关联 TOTP；主窗口关闭、Vault 锁定及取消授权时行为正确。
3. Mac 终端通过 SSH Agent 使用关联密钥；用户能辨认授权范围，不声称自动验证最终 SSH 目标主机。
4. 完整导出后在空目录分别使用主密码或恢复密钥恢复，核对凭据、历史、候选、关系与回收站；原工作库不被覆盖。

## 3.5 Bitwarden 迁入边界

P0 适配 Bitwarden 普通 JSON 与 Password protected 加密 JSON；后者需要专门的格式解密、KDF 参数校验和验证向量，不能直接调用 OVB 解密器。Account restricted 导出绑定原账户密钥，不纳入迁入入口。[R21][R22]

支持范围为登录信息、多个网址及匹配规则、TOTP、安全笔记、文件夹、收藏、自定义字段和可表示的 Ed25519 SSH 材料；以实际导出字段为准。密码历史仅保留来源实际携带的信息，不捏造历史或启用时间。无法映射的 URI 匹配规则保留原值并禁用该规则的自动填充，不能扩大为域名级匹配。

Passkey、卡片、身份、附件、不支持的密钥及字段均在预览和报告中列明，不静默跳过。组织拥有的数据需另行导出并满足来源权限；个人导出不能被解释为已包含全部组织资料。暂不要求用户提供真实保险库文件，先以虚构样本验证。

用户确认来源命名空间后，以来源条目 ID 和内容摘要识别重复；同源同内容再次导入跳过，同源内容变化显示差异并由用户选择更新或保留副本。缺少可靠来源 ID 时只能提供候选重复项，不按域名/用户名直接覆盖。导入前生成恢复点，确认后以事务提交业务记录和导入映射；失败不留下半批结果。完整 OVB 恢复另走第 17 章，不当作普通记录导入。

解析器限制文件大小、字段长度、层级及 KDF 资源；不创建持久明文中间文件，报告不输出秘密。源文件本身可能为明文，提示用户自行保管或删除，不承诺 SSD 安全擦除。

# 04. 统一账号与凭据数据模型（参考 CXF）

## 4.1 设计依据

参考 FIDO Alliance Credential Exchange Format（CXF）1.0 的 Item / Credential 可组合思路：一个 Item 可以携带多种凭据。CredPivot 内部定义自己的稳定实体 ID、关系与内容修订信息；CXF 导入导出映射留待后续兼容阶段。CXF 是交换格式参考，不是 SQLCipher Schema，也不是 OVB 加密容器。[R01]

## 4.2 逻辑实体

| 实体 | 职责 | 关键字段（逻辑层） |
|:--|:--|:--|
| Vault | 单个独立保险库 | vault_id、格式版本、策略 |
| Item / Account | 某网站/服务/项目的凭据聚合 | id、名称、URL、标签、分组、图标 |
| Credential | 可组合的登录/认证对象 | id、item_id、type、data、revision |
| LoginSecret | 账号密码 | 用户名、密码、生成/启用时间、匹配规则 |
| TotpSecret | 时间型 OTP | Base32 种子、issuer、算法、period、digits |
| SshIdentity | SSH 身份材料 | 算法、公钥、私钥、注释、指纹、使用规则 |
| SshHost | 连接目标 | 主机、端口、用户、Host Key 指纹、密钥关联 |
| RecoveryCodeItem | 网站备用恢复码 | 服务、密文码列表、已使用标志 |
| PasswordHistory | 历史密码 | 归属、密文、产生/启用/退役时间 |
| SecretNote / Token | 其他敏感信息 | 类型、字段、可见/隐藏策略 |
| Revision | 当前内容版本与过期编辑校验 | 随机 revision_id；P0 不建完整因果图 |
| ImportMapping | 来源追踪与重复检测 | 来源命名空间、来源条目 ID、内容摘要、本地 ID |
| PendingPassword | 待启用密码候选 | candidate_id、base_active_revision、候选值、生成时间、状态 |

实体之间允许一对多和多对多链接。例如一把 SSH Key 可用于多台主机，一个账号可关联多个登录身份与 TOTP；关联表变化与所属实体内容修订在同一业务事务中完成；未来同步必须保留该原子边界。所有外键关系在解锁后的数据库中维护，不将业务 ID、网址或用户名暴露到远程明文文件名。

## 4.3 时间字段语义

- `created_at`：记录在 CredPivot 中首次创建时间；导入后仍为导入时间。
- `password_generated_at`：当前随机密码被生成的时间（可能还未在网站启用）。
- `password_activated_at`：用户确认已在网站实际启用的时间；提醒以此为主要基准。
- `password_changed_at`：CredPivot 内密码内容最近被修改的时间；可与启用时间不同。
- `last_verified_at`：用户最近确认有效的时间；不能自动替代实际启用时间。
- `retired_at`：旧密码退役时间。

未知的实际启用时间必须保留为未知，不可把导入日偷偷当作启用日。这些名称表示业务语义；生产 Schema/协议统一采用对应的 `_ms` 后缀字段，以 UTC Unix 毫秒存储，UI 根据用户时区显示，示例见附录 A。

## 4.4 不允许被无意丢弃的扩展字段

任何 CXF 不包含或其他软件不支持的字段（如同步修订、历史 N 条、SSH 授权策略），必须通过显式转换器处理。导出前显示兼容性报告：可保留、降级、自定义扩展、无法导出。不能声称“CXF 兼容”就能保证所有字段无损往返。

## 4.5 单机数据与未来同步的最小边界

1. Vault、Item、Credential、历史及候选使用稳定随机 ID；不依赖 SQLite 行号、路径、设备硬件 ID 或时间戳生成身份。业务修改产生新的内容修订 ID，读取、复制、搜索不产生内容修订。
2. 所有业务写入统一通过 Core；提交时校验调用者的预期修订，过期编辑返回差异并保留用户未保存内容，不静默覆盖。P0 不要求无限修订历史、父版本 DAG、设备序号、Outbox 或冲突合并器。
3. 可移植业务数据包括凭据、关系、策略、历史、候选、回收站和必要导入映射。设备本地数据包括使用记录、UI 布局、路径、快捷解锁包装及未来网络凭据；不进入可移植业务快照。搜索索引、安全检测结果等派生数据恢复后重建。
4. 数据库 Schema、逻辑数据格式、加密信封和未来同步协议分别版本化。未知关键字段或版本拒绝写入；可忽略扩展也须原样保留，无法保留则只读。
5. 删除与恢复采用显式业务操作；P0 只维护当前回收站状态，不为尚未启用的同步无限保留永久删除日志。首次同步以当时完整状态建立基线，随后才产生同步删除标记和变更日志。
6. 恢复副本默认独立使用，不自动合并两份分别编辑过的库。启用同步时分配新的设备身份和同步代际，具体规则见第 15 章。

# 05. 密码管理器功能规格

## 5.1 凭据创建与使用

支持手动新增、浏览器提示保存、导入、密码生成器；字段包括标题、服务 URL、用户名、密码、标签、说明、自定义字段、关联 MFA / SSH 身份。浏览器从注册或密码修改表单捕获后必须请求用户确认，不可在未知页面后台默默写入。

密码生成器应支持随机字符、长度、字符集、排除歧义字符与词组密码。使用操作系统安全随机源。默认推荐高熵随机生成，而不是依靠复杂但容易预测的用户模式。支持一键复制并设置剪贴板清理策略，但不保证第三方剪贴板历史功能已经被清除。

## 5.2 密码生命周期与提醒

**确认规则：默认启用 90 天检查提醒，用户可以全局或按单条凭据覆盖；提醒不代表强制过期。** 用户可选 30/60/90/180/365 天及关闭。判断时优先使用 `password_activated_at`；未知时显示“启用时间未知”，邀请用户确认，而非重置时钟。

到期提醒的含义是“检查是否需要修改密码”。若证实账号已泄露或密码被重用，系统可以提供高优先级建议；不能擅自自动更改远端网站密码。NIST SP 800-63B 不支持无泄露依据的强制周期性密码更换，本产品仅提供可选提醒工具。[R06]

## 5.3 密码启用与历史

- 默认保留最近 10 个旧密码，不计当前值；可设置 0 至 50 条，单条可覆盖。待启用候选不受历史条数裁剪；未来同步的未解决冲突也不得按历史上限删除。
- “生成新密码/准备修改”创建待启用候选，记录 `candidate_id`、`base_active_revision` 及生成时间。`base_active_revision` 指向当前已启用密码的版本 `active_password_revision`，不等于整个 Credential 的修订号；保存候选会产生 Credential 新修订，但不改变已启用密码版本。候选与当前密码分开显示、分开复制；普通自动填充继续使用当前已确认值。
- 用户确认网站已更新后，才在一个事务中把旧值移入历史、候选切换为当前、记录启用时间并更新内容修订。手动编辑也必须明确选择“已在网站启用”或“先保存候选”。浏览器捕获成功提交不能自动证明网站已经接受密码。
- 网站修改失败可保留或丢弃候选，不改变当前值。未来同步候选时，另一设备也不得因收到候选就替换当前填充值。
- 确认时若 `active_password_revision` 已不同于候选的 `base_active_revision`，进入版本核对，不把过时候选直接覆盖新密码。校验通过时在最新 Credential 上激活，保留其他最新字段，并同时产生新的凭据修订和已启用密码版本。P0 的 UI 与 Chrome 入口由统一写入者串行处理，并校验预期修订；未来多设备并发确认再按整凭据冲突处理。
- 首次新增/导入可由用户指定当前可用密码，实际启用时间未知时保持空值；不为追踪时间强迫用户再次修改网站密码。
- 恢复历史值先产生待启用候选；只有用户确认网站也使用该值时才激活。保留旧值的生成、启用、退役时间，不改写原记录。
- 历史裁剪使用协议规定的稳定顺序：可信业务状态中的退役时间排序，时间相同以不可变 revision_id 排序。此顺序仅用于展示与裁剪，不决定并发版本胜负。P0 仅裁剪已退役历史，不裁剪待启用候选；后续合并须先保留冲突，再按同一稳定规则裁剪。
- 上限只限制当前逻辑 Vault 的历史内容；旧快照、Git 备份和离线设备可能仍保存更早密文。

## 5.4 搜索与安全中心

搜索支持服务名、域名、用户名、标签、收藏、类别；搜索索引只驻留已解锁 SQLCipher 或内存，不生成持久化明文索引。安全中心展示弱密码、重复密码、未知启用时间、检查提醒及本地使用记录。未保存 TOTP 只显示“未记录 MFA 信息”，不能推断网站没有 MFA；用户确认使用外部验证器/硬件密钥后记录相应状态。检查提醒单独分组，不将“满 90 天”标成密码已泄露。所有可本地完成的检测默认离线执行。

## 5.5 删除与回收

删除先进入加密回收站，保留稳定 ID、删除时间和恢复所需关联；恢复时产生新内容修订。单机永久删除可清理当前内容，未来启用同步后另行记录 Tombstone。用户可恢复或永久删除逻辑记录；界面需说明外部历史快照和旧设备可能仍保留此前密文。对高风险秘密建议轮换真实网站凭据，而非仅删除 Vault 项。

# 06. MFA 管理功能规格

## 6.1 TOTP

P0 实现 RFC 6238 TOTP，支持常见 6/8 位、30 秒默认周期以及 SHA-1 / SHA-256 / SHA-512（按凭据参数）。支持扫描二维码、读取 `otpauth://` URI、手动输入 Base32 种子、备份和恢复。显示剩余有效时间，临近过期时应避免复制即将失效的码。[R07]

MFA 可在账号详情作为关联 Credential 显示，浏览器填充时根据已确认的网站 Origin 和用户选择推荐对应验证码。不能仅因为页面出现六位输入框就自动提交 TOTP。

## 6.2 备用恢复码

网站提供的恢复码属于该网站的凭据数据，与 CredPivot 自身的 Vault 恢复密钥分开存储和命名。支持录入多条、复制单条、手动标记已用和剩余数量。每条码使用稳定 ID，本机修改校验预期修订，复制不自动等同于使用成功。未来同步时整组并发更改须保留候选，不能保证离线双设备不会同时尝试同一码。用户若同时把密码与 TOTP 种子放在同一 Vault，应说明其便利性与“单点泄露可暴露多个认证因素”的风险。

## 6.3 HOTP 与 Passkey

HOTP 因设备间计数器冲突涉及特殊同步语义，计划放到 P1；Passkey 的平台凭据提供与迁移涉及 WebAuthn / FIDO 交互和更复杂的权限限制，P1 单独设计。V1 模型应允许新增 Credential 类型，但不提前承诺未实现的系统 API 能力。

# 07. SSH 管理功能规格

## 7.1 密钥与主机管理

P0 生成和导入 Ed25519 OpenSSH 私钥（包括受密码保护的输入）；RSA/ECDSA 延后 P1，遇到不支持格式给出明确错误，不自动转换或降级。展示公钥、指纹、注释、用途、创建日期、使用范围、关联账号/主机。私钥默认保留在 Vault 内，不应为了日常 SSH 操作而自动导出为磁盘明文文件。

主机模型包括 hostname、port、username、host_key_fingerprint、备注、JumpHost（P1）和多个身份候选。用户修改已记录的主机公钥指纹必须确认。P0 不接管 SSH 客户端的 known_hosts 校验，也不声称 Agent 能观察所有服务器指纹变化；实际连接仍由 SSH 客户端校验。

## 7.2 桌面 SSH Agent

P0 在 macOS 提供 SSH Agent 兼容接口，由独立 Vault Agent 持有短期解锁上下文并执行签名请求。策略分为“已授权会话允许”“每次签名确认”“高安全每次生物识别确认”。支持按密钥、调用来源、会话定义授权限制。

SSH Agent 通常不能从通用签名请求中可靠证明最终 SSH 主机身份，因此不能把“自动识别所有最终目标主机”视作安全前提。无法可靠绑定目标的请求，应采用用户可理解的保守授权规则。

## 7.3 SSH 与 Git 的联动

同一 GitHub Item 可以关联网页登录密码/TOTP 和 Git over SSH 的 Ed25519 密钥。在终端执行 `git push` 时，Vault Agent 根据用户配置提供密钥签名，浏览器则使用同一 Item 的网页登录凭据。P1 的 Git 单向备份自身首次认证要支持独立外部 Git Token/系统 SSH 密钥，避免“必须先解密 Vault 才能取得克隆 Vault 的 SSH 密钥”的循环依赖。

## 7.4 移动端边界（后续）

Android 后续可复用密钥查看、生成和导入/导出能力；不承诺像桌面系统一样向所有第三方 SSH 客户端暴露全局 Agent。涉及私钥导出和复制的操作均需二次确认与本地授权。

# 08. 三模块联动与核心用户旅程

## 8.1 关联演示：GitHub 工作账号

```text
Item: GitHub / Work
  Login Credential  -> github.com (username + password)
  TOTP Credential   -> issuer=GitHub (TOTP seed)
  Recovery Codes    -> GitHub backup codes
  SSH Identity      -> Ed25519 key for git@github.com
  Ssh Hosts         -> github.com; associated work machines
```

## 8.2 首次创建 Vault

1. 选择创建保险库、从 Bitwarden 迁入或恢复 OVB；Bitwarden 迁入先创建本地 Vault，OVB 恢复进入独立目标目录。
2. 创建时可选合规本地目录，输入并确认主密码；核心生成随机 VMK、恢复密钥及两个独立包装槽。
3. 保存恢复密钥并完成校验，初始化本地数据库、格式版本及本机安装身份，不创建同步队列。
4. 可选绑定 Touch ID，连接 Chrome 扩展，配置本地恢复点及外部归档位置；没有 WebDAV 配置步骤。

## 8.3 Chrome 保存与填充密码

1. 扩展后台核验网页 Origin、tab/frame/document 和用户操作，内容脚本不自行声明可信来源。
2. 用户确认后通过 Native Host 把最小字段提交 Agent；Agent 检查扩展身份、会话和权限。
3. Core 在 SQLCipher 事务中校验预期修订并保存 Credential、候选或密码历史；仅事务成功后返回“本地已保存”。
4. 填充时用户选择账号；需要解锁则通过 Mac 原生授权，返回单条所需秘密前及实际填充前再次检查授权和页面身份。
5. App 主窗口关闭不代表 Agent 停止或 Vault 已锁定；锁定、取消、页面导航或连接断开使等待请求失效。扩展不显示“待同步”等未实现状态。

## 8.4 本机过期编辑

Mac UI 和 Chrome 同时打开同一记录时，先提交者更新修订；后提交者的预期修订不符则提示重新核对，并保留其未保存内容。不能因为只有一台设备就让后写入的旧页面覆盖新密码；也无需为此引入多设备合并引擎。

## 8.5 找回主密码

以完整 OVB 归档及恢复密钥，经 GUI 或独立 CLI 在空目录生成可验证副本，再设置新主密码。核对通过后才显式切换使用，原工作库保持可用。恢复不依赖原设备 Keychain、CredPivot 在线账户或 WebDAV。若主密码和恢复密钥同时丢失，则无后门恢复。

## 8.6 首次启用同步（后续）

升级客户端后先生成独立备份，再以当前完整逻辑快照建立同步初始基线。生成新的同步代际和设备身份，从该基线开始跟踪变更；不重放整个单机历史。不得自动把其他本地副本当作已同步成员，详细约束见第 15 章。

# 09. 跨平台交付与浏览器扩展

## 9.1 首发平台与最低版本

| 组件 | 产品基线 | 首发交付与验证边界 |
|:--|:--|:--|
| Mac 应用 | M 系列 Apple Silicon arm64、macOS 15+ | 最低版与发布时支持的稳定大版本及补丁版形成验证清单；不支持 Intel |
| Mac Chrome 扩展 | 发布时最近两个稳定主版本 | 与 Mac App 配套交付，Native Messaging；Beta/Canary 不计入支持 |
| Android、其他平台和浏览器 | 后续 | 不属于本次发布或验收条件 |

macOS 15 为当前产品下限建议；框架最低可运行版本不等于本产品已验证支持。发布时依据 Apple 安全更新和 Flutter 支持矩阵固定清单，不把“15+”解释为自动兼容未来系统，也不把最近几代更新视作永久维护合同。[R17][R18]

Mac 构建机可要求更高系统，不据此自动提高部署下限。无可用 Touch ID 或设备包装失效时回退主密码，不能无认证解锁。

Mac 应用采用签名、公证的直接分发；Chrome 扩展采用 Chrome Web Store 发布路径，开发期可加载未打包扩展验证，正式交付须形成可安装的商店版本并验证稳定扩展 ID、Host 注册及两者版本兼容。商店审核周期属于发行依赖，不能以仅开发者模式可用宣称首发完成。

Android 14/API 34 暂作后续候选；实际实施时重新核对系统、工具链和设备支持，不在本版冻结 Android 构建或发布参数。

## 9.2 浏览器扩展必须依赖应用

**强制规则**：未安装 CredPivot 的浏览器扩展只能展示连接/安装引导；已安装但 Agent 不可达时不能独立解密、浏览、修改或同步 Vault。扩展不建立 SQLCipher/IndexedDB 独立保险库，不持久化 VMK、主密码或登录秘密。主应用窗口可以关闭，但配套 Agent 必须能够在授权条件下按需运行。

浏览器内容脚本只定位字段和执行一次已授权填充。网页不能自行声明可信 Origin。扩展后台从浏览器提供的 sender/tab/frame/document 信息取得页面身份，验证顶层与子框架的关系、站点匹配及用户操作，再通过已配对连接向 Host 请求最小字段。[R10]

Host 核验扩展来源、连接配对、请求类型、会话与操作权限；它无法仅凭 Native Messaging 独立证明网页 Origin。扩展后台是可信计算边界的一部分，遭攻陷的授权扩展不在“仍可证明页面真实身份”的保证内。配对不提升网页身份可信度。

填充授权绑定请求、Vault、凭据、tab/frame/document 和短有效期；真正填充前再次检查页面身份，导航、锁定、连接断开或目标变化使请求失效。未知来源、跨域 frame、HTTP 默认不自动填充，不以子串匹配域名。候选列表只给必要元数据；秘密只在用户选择后按单条请求返回，普通内容脚本无全库搜索/导出权限。

## 9.3 扩展核心页面与行为

扩展弹窗包含当前站点推荐账号、搜索、复制 TOTP、密码生成、保存/更新、锁定状态、连接状态及“打开 CredPivot”。网页默认不无条件自动填充；用户可选择“此站点自动建议/点击填充”，对 HTTP、相似域、跨域 iframe、未知 Origin 进行保守处理。

浏览器插件状态必须可识别：“未连接 App”“Vault 已锁定”“已连接”“保存中”“本地已保存”“保存失败”。Native Host 不可用时不能伪造保存成功。

## 9.4 Android 系统填充与身份边界（后续设计约束）

Android 不在首发创建工程或交付系统服务。后续优先复用 Rust 核心与 OVB，使用应用私有工作库，Kotlin 负责 Keystore/BiometricPrompt、AutofillService 与 Credential Provider 的平台入口。[R11][R19]

平台解锁和填充须能在 Flutter 主窗口未运行时按需启动；不照搬 Mac 常驻 Agent。调用应用身份、网页域名及用户授权分别校验，取消、超时或进程回收后废弃授权。正式开发前再验证进程模型、系统最低版本及冷启动行为，不以本节代替 Android 原型。

# 10. 现代化 UI 与交互设计规范

## 10.1 产品体验定位

视觉取向为**专业、安静、轻量、可信赖**，避免传统密码管理器过度密集的表单式界面，也不把安全警告全部做成刺眼的红色。统一的低噪声界面让用户在几秒内找到服务、识别凭据类别、完成当前任务。

设计系统命名为 `CredPivot Design System / CPDS`，共享颜色、字重、间距、圆角、动效与状态 Token，P0 先实现桌面；移动端仅保留复用视觉语义与业务模型的方向，不实现移动布局。

## 10.2 全局信息架构

**桌面主导航**：总览、全部凭据、密码、MFA、SSH、收藏、安全中心、备份与恢复、设置。默认左侧导航 + 中间凭据列表 + 右侧详情检查器，窗口较窄时折叠为双栏或单栏；全局搜索和“新增”是始终可见的首要操作。

**后续移动导航草案（非 P0）**：保险库、验证器、SSH、设置，顶部搜索与新增；账号详情采用分区卡片展示关联 Login/TOTP/SSH，不强迫用户跳转三次。适配单手使用和系统大字体。

## 10.3 视觉基础 Token（初稿，可经 UI 验证微调）

| Token | 默认建议 | 说明 |
|:--|:--|:--|
| Base spacing | 4 px 基础网格；常用 8/12/16/24 | 减少临时布局值 |
| 组件圆角 | 10–14 px | 卡片现代但不过度胶囊化 |

## 10.4 核心页面详细交互

**首次引导（向导式）**：选择创建/Bitwarden 迁入/OVB 恢复 → 本地目录与主密码 → 保存恢复密钥并验证 → 可选 Touch ID → 连接 Chrome → 备份说明。OVB 恢复走独立目录与原归档解锁流程，不先创建空库覆盖归档身份。单步有清楚的主操作、帮助、错误恢复，不以营销说明干扰安全操作。

**保险库列表**：支持卡片/紧凑列表切换，图标 + 标题 + 用户名 + 凭据类型标记。悬停/轻扫显示复制用户名、复制密码、查看 OTP、打开网站；复制秘密前考虑锁定与重新验证策略。搜索结果可显示关联账号集合，避免同站点多账号混淆。

**详情抽屉**：首屏展示登录身份、域名和核心操作，当前密码与待启用候选分区显示，按钮明确标注用途；密码默认遮挡，点击眼睛暂时查看；下方按“登录 / MFA / SSH / 历史 / 备注”分段。编辑采用显式保存与取消，离开未保存的敏感修改时明确提示。

**安全中心**：不要只展示抽象分数。优先展示“重复密码 8 项”“已到期检查 12 项”“未记录 MFA 信息的账户 4 项”“备份尚未验证”等可执行事项，并提供一步到达对应账号。

**备份与恢复**：分别展示本地恢复点、手动归档、上次成功时间和恢复验证状态；本机恢复点明确标为不能防设备丢失。备份失败显示原因与重试入口；P0 不显示同步入口、设备列表或未实现的 Provider 配置。

**SSH 操作授权（Mac）**：弹出原生风格的明确确认卡，显示使用的是哪把密钥、操作类别、调用来源及该次/该会话授权范围；不可将未知来源请求包装成“已验证目标服务器”。

## 10.5 交互标准与无障碍

- 快捷键：全局搜索、快速锁定、复制当前凭据、创建记录；可在设置中查看并自定义部分组合。
- 所有异步保存/导入/备份动作必须有明确完成、失败、可重试状态；禁止静默吞错。
- 所有危险动作（删除最后一份备份、导出明文、替换 SSH 私钥、密钥轮换）均使用可理解的分级确认。
- 支持键盘全操作、屏幕阅读器语义、可聚焦控件、色彩对比度与系统大字号；以 WCAG 2.2 AA 为设计检查基线。[R15]
- 支持减少动效和系统主题；不会只用颜色区别保存成功、失败和过期编辑。
- 空状态提供下一步动作，弱网络状态可离线继续；指纹失败应解释主密码回退路径。

## 10.6 UX 验收用例

从打开桌面应用到搜索并复制一个已解锁密码，目标 3 个以内的明确操作；新增账号时能够直接关联 TOTP；用户可在详情页看到密码何时生成、实际启用、何时检查和保存的历史个数；浏览器新增后本机列表立即可见，扩展与 App 显示同一已提交状态；备份状态单独显示。以上是操作设计目标，发布前以可用性测试验证。

# 11. 系统分层架构与工程选型

## 11.1 总体逻辑分层

```text
Mac Flutter UI     Mac Chrome Extension
       |                    |
       |                Native Host
       +----------+---------+       SSH socket
                  |                     |
                  +-- Mac Vault Agent --+
                            |
                      Rust Vault Core
                      /             \
             SQLCipher 工作库     OVB 完整加密归档
```

Mac Agent 是唯一工作库运行时所有者。所有业务写入由 Core 统一校验与事务提交，UI、扩展和 Host 不直接写库。跨平台边界放在系统安全存储、授权、文件位置和进程生命周期；不把 Mac 路径、Keychain 引用或 UI 类型写进业务格式。

## 11.2 建议技术栈

| 层 | 实现 | 首发职责 |
|:--|:--|:--|
| 核心库 | Rust stable | 数据模型、事务、密码学、导入、OVB、OTP、SSH |
| 密码学 | 成熟 Rust/系统库 | Argon2id、HKDF、AES-GCM、随机数、Ed25519 |
| 工作库 | SQLCipher + Rust 绑定 | 固定版本、配置、迁移和一致性恢复 |
| Mac UI | Flutter / Dart | 本机管理、授权交互、导入备份；不提前实现 Android UI |
| Mac 适配 | Swift | Keychain/Touch ID、系统生命周期、目录权限 |
| Chrome 扩展 | TypeScript + WebExtensions | 保存、选取、填充、TOTP、生成、锁定与连接 |
| Agent / Host | Rust | 受限 IPC、Native Messaging、SSH、统一会话 |
| 恢复 CLI | Rust | inspect、verify、recover 与显式逻辑导出 |

不引入 Go 常驻服务，也不为未来同步另建服务器。语言与模块选择服务于当前职责，不要求首日拆成多个独立 crate。

## 11.3 API 与进程边界

- Core 暴露数据操作、候选激活、解锁/锁定、OTP、SSH、迁入、归档和恢复；各入口按角色授权。
- Agent 通过文件锁保证一个 Vault 只有一个运行时写入者，持有唯一解锁会话。窗口关闭后是否仍解锁遵循第 18 章策略。
- Native Host 只校验与转交受限请求，不持有长期 VMK；普通内容脚本无全库枚举或导出权限。
- 平台适配只围绕实际需要隔离 Keychain、解锁、通知及路径等能力，不提前添加空的 Kotlin 或云适配器。
- Schema 迁移独占 Core，Chrome/SSH 入口明确返回维护中；密码学材料不进入通用 Dart 状态，单条显示秘密保持最短必要生命周期。

未来 Android 按系统生命周期接入相同核心，未来同步在 Core 业务事务处增加变更记录。P0 不运行轮询、网络上传、同步队列或冲突合并器。

# 12. SQLCipher 本地持久化与 Vault 目录

## 12.1 使用 SQLCipher 的理由与限制

SQLCipher 作为正式本地数据库引擎，提供成熟的 SQL、索引、事务与数据库页面级透明加密，不需要开发团队自造关系查询引擎。它基于 SQLite 生态，本身不需要数据库服务进程。[R03]

其代价包括：需要打包 SQLCipher 与密码学 Provider、处理 Flutter/Rust FFI 和各平台编译链、升级兼容测试，以及运行时可能创建 WAL/SHM/临时文件。正式发行前必须测量 Mac App 与 Chrome 扩展的 Release 安装体积，不对尚未测量的二进制增量作数字承诺。

## 12.2 Vault 存储目录策略

Mac 首次启动向导可选择目录，不选择即使用系统默认应用数据目录；未来 Android 工作库固定在应用私有目录。Mac 自定义目录需校验可写权限、剩余容量、符号链接/路径逃逸、文件系统原子替换与锁能力。默认禁止把正在使用的数据库直接放在 WebDAV 挂载目录、网络共享、第三方实时云盘同步目录或不保证 SQLite 文件语义的位置。Mac 可在设置中查看和迁移。

**macOS**：真实 SQLCipher 数据库可保存在用户授权的本地目录。**后续 Android 约束**：使用应用私有数据库目录；系统文件选择器选到的外部位置主要作为加密归档导出或备份位置。不能保证所有移动端 SAF/文件提供器路径都支持数据库随机读写、锁和 WAL。UI 应区分“工作 Vault 位置”和“导出/备份位置”。

## 12.3 建议目录结构

```text
CredPivotVault/
  vault.json             # OVB1 version + wrapped VMK slots
  vault.db               # local SQLCipher database (encrypted)
  runtime/               # implementation-owned auxiliary files
  backups/               # optional local encrypted packages
```

运行期间 SQLCipher 可能生成 `vault.db-wal`、`vault.db-shm` 等辅助文件。数据库 WAL 中包含加密页，SHM 为数据库同步元数据，临时文件仍需专项审计。不得用直接复制打开状态下的 `.db` 文件作为一致性备份。[R03][R04][R05]

## 12.4 数据库逻辑 Schema（P0）

| 表/领域 | 内容 | 一致性约束 |
|:--|:--|:--|
| `vault_meta` | Vault、逻辑版本、Schema 版本 | 按迁移计划升级；不混用协议版本 |
| `items` / `credentials` | 账号、凭据、回收站状态、当前修订 | 稳定随机 ID、关联完整、预期修订校验 |
| `password_history` / `pending_passwords` | 退役历史、待启用候选 | 激活与历史更新同一事务 |
| `ssh_hosts` / 关系表 | 主机与身份、账号关联 | 所属操作原子提交 |
| `import_mappings` | 来源命名空间、来源 ID、摘要、本地 ID | 随导入记录同事务提交，避免重复导入 |
| `settings` | 可移植业务策略 | 密文保存 |
| 本机设置与备份状态 | 路径、使用记录、恢复点索引、验证状态 | 与可移植业务数据分开；不作为内容修改 |

P0 不创建 `sync_outbox`、`sync_inbox`、`sync_devices`、`sync_conflicts`、远端控制链或完整因果图。未来同步阶段通过 Schema 迁移增加，启用前从完整快照初始化。

索引只驻留加密库或内存；公开元数据仅限解锁必要参数。数据库迁移先创建并验证一致性恢复点，再独占升级、检查完整性、提交版本；失败保留原库和恢复点。

## 12.5 事务示例：确认启用候选密码

```text
BEGIN IMMEDIATE
  1. 校验入口授权、预期 Credential 修订及候选 base_active_revision
  2. 不一致则返回过期编辑，保留用户输入，不改写当前密码
  3. 将旧当前值写入 PasswordHistory
  4. 候选切换为当前值，更新启用时间及两个不同用途的修订 ID
  5. 按稳定规则裁剪退役历史，保留其他候选和关联字段
COMMIT
```

提交完成才向 App/Chrome 返回保存成功。候选保存不执行激活和历史退役；崩溃后的重复确认须检查候选状态，不能再次追加历史。未来增加同步操作记录时，应与同一业务事务提交，而非在 UI 保存回调中拼接日志。

## 12.6 数据库密钥来源

主密码不直接喂给 SQLCipher。主密码经 Argon2id 派生 KEK，解出随机 VMK；由 VMK 通过带域分离的 HKDF 派生数据库原始密钥，再交给 SQLCipher。由此可实现独立恢复密钥、生物识别快捷解锁与对数据库密钥的统一管理；须在实现中固定原始密钥配置及 SQLCipher 兼容参数。[R03]

## 12.7 存储位置迁移

关闭写入入口 → 形成一致性数据库副本 → 将全部 Vault 组件复制到新位置 → 校验 SQLCipher 完整性、控制配置与业务关系 → 原子更新本机路径指针 → 重启 Agent 与数据库连接。任何环节失败则保持原路径可用。旧目录的普通删除不能视为密码学安全擦除，特别是 SSD、快照和云盘历史场景。

# 13. 密钥体系、加密与恢复

## 13.1 不作绝对暴力破解承诺

离线保险库没有服务端限速。攻击者一旦获得完整密文，就可以在自己的设备上反复猜测主密码；KDF 只能提高猜测成本，无法对弱密码给出“绝对不可破解”的承诺。安全目标是采用高熵主密码、内存困难 KDF、足够随机盐、强认证加密、无后门，并针对暴力猜测进行成本测试。

## 13.2 密钥层级（拟定规范）

```text
Master Password                 Offline Recovery Key (256-bit)
      |                                      |
 Argon2id + salt                        HKDF + salt
      |                                      |
   KEK_master                              KEK_recovery
      |                                      |
      +------ AEAD-wrapped VMK slots --------+
                              |
                    Random 256-bit VMK
                    /        |        \
         HKDF(local-db)  HKDF(ovb)  HKDF(blob)
              |             |           |
         SQLCipher Key    Snapshot        Attachments (future)
```

1. VMK 在 Vault 创建时由 CSPRNG 随机生成，长度为 256 bit。
2. 每个主密码 Key Slot 独立随机盐；Argon2id 参考 RFC 9106 的内存受限推荐配置（64 MiB、3 次迭代、4 lanes）作为实测起点。[R02] 参数写入槽并参与认证；读取时使用记录参数，不按设备自行换值。考虑后续移动端资源预算，不只按高配 Mac 调高成本；当前不承诺 Android 性能。未来需要升级参数时显式重包装，不为手机另开弱密码槽。
3. 恢复密钥由 CSPRNG 生成 256-bit 秘密，人类可读格式通过 Base32 分组与校验码展示，不使用短数字码作为唯一离线恢复凭证。
4. KEK 使用 AES-256-GCM 包装 VMK，每个包装具有全新 nonce；AAD 绑定 Vault ID、Slot ID、类型、格式版本及参数编码。
5. 派生本地数据库、OVB 对象和配置完整性密钥时，使用明确的 HKDF 域分离标签，避免同一个密钥跨用途复用。附件密钥域仅留作后续扩展，不在 P0 实现附件模块。
6. OVB 对象使用 AES-256-GCM；以 VMK、Vault ID、对象类型和随机 256-bit 对象 ID 经 HKDF-SHA256 域分离得到对象子密钥，每个对象只封装一次，使用随机 96-bit nonce。内容变化必须换对象 ID、子密钥与 nonce；重试复用原密文字节。准确的 HKDF salt/info 编码、AAD 和信封布局在 M1 形成字节规范与跨实现向量，未通过前不用于真实秘密。Blob 仅为后续预留。
7. 控制配置采用独立 HKDF 域派生的 HMAC-SHA256 密钥认证整个配置（含 Vault 身份、所有 Key Slots 和版本，排除认证标签自身），防止单槽有效而整体被拼接/删改。持有 VMK 的人能生成合法配置；这是完整信任模型，不提供恶意成员隔离。P0 仅认证本机当前配置，不实现远端控制链。
8. 使用成熟密码学库而非自制算法。解锁前先限制 Header 长度、KDF 参数和解析深度，再做 KDF；认证完成前不采用业务配置。密钥短时保留，锁定后清理可控内存并停止敏感 IPC。

## 13.3 生物识别快捷解锁

首次使用主密码解锁后，应用可在本机创建受系统保护的设备密钥，并以其包装 VMK 的设备本地副本。后续通过 Mac Touch ID 授权解开本地包装；该包装不进入可移植归档，也不能用于其他设备。未来 Android 使用自身系统授权与密钥存储适配。更换设备、重装或密钥丢失时需主密码/恢复密钥重新建立设备授权。

设备指纹不是可供应用导出的对称密钥材料；生物识别只作为操作系统访问受保护密钥的授权条件。系统解锁策略、失败回退、设备重启后重认证和高级风险操作二次确认都须在平台层测试。

## 13.4 修改主密码与安全密钥轮换

**P0 为本机改密，不依赖网络、ETag 或远端配置链。普通改主密码不改变 VMK。**

1. 要求当前授权并独占 Vault 管理操作，暂停新业务写入；先生成可恢复的加密恢复点。
2. 在本机创建新随机盐与 nonce、主密码包装槽及递增的本地配置版本，保留独立恢复槽；校验新主密码可解出同一 VMK 及整个配置认证标签。
3. 新配置写入受保护临时文件并完成持久化，再原子替换 `vault.json`；旧配置在替换确认前保持可用。数据库密钥不变，无需把改密与数据库重加密跨文件硬凑为一个事务。
4. 重启后按原子提交结果使用当前有效配置；不能只按临时文件时间或最大版本猜测成功。清理未提交材料，检查当前密码解锁成功后再报告改密完成。完整崩溃阶段规则和文件持久化步骤须在 M1 定稿并验证。

新主密码只保护当前包装槽和此后归档；旧主密码仍可能通过旧备份或恢复点解出同一 VMK。改密不宣称撤销历史副本访问能力。

**安全重建**用于 VMK、恢复密钥或设备可能泄露：在新目录生成新 Vault ID、VMK、恢复密钥及配置，复制当前完整逻辑状态并重新加密，保留稳定业务 ID；独立验证恢复后才显式切换。新库重建本机快捷解锁包装，旧库保留或删除须由用户决定。安全重建不能撤销旧明文和历史密文，网站密码、TOTP 或 SSH 密钥仍需按泄露范围在真实服务轮换。

后续同步阶段重新设计控制配置并发提交和撤销流程，不能沿用“先上传可解 VMK 的候选槽，再声明未提交所以不可用”的假设：一旦候选密文与对应密码可得，逻辑作废并不撤销其解密能力。

## 13.5 恢复密钥的正确语义

恢复密钥是独立高熵的第二个解锁入口，**不是可以从 Git 历史中彻底撤销的“一次性恢复码”**。应在产品中称为“保险库恢复密钥”。如用户认为该密钥已泄露，应执行完整密钥轮换与重新发布备份，而不是只删除当前 `vault.json` 的旧 Key Slot。

## 13.6 独立恢复要求

必须同时交付公开的 OVB/crypto 规范、兼容参数、Schema 映射、加解密测试向量和 `credpivot-cli`。P0 CLI 支持 `inspect`、`verify`、`recover` 和完整逻辑数据导出；`export-cxf` 延后兼容阶段；主密码通过交互式安全输入获取，不经命令行参数或 Shell 历史传递。第三方不依赖 CredPivot 专有服务器，也能依据规范实现恢复器。CLI 可以复用 Core，但这不等同于协议独立实现：发布门禁另要求依据公开规范、使用独立解析路径验证解密和快照恢复向量。完整逻辑导出必须包含关系、历史、候选、回收站及迁入映射；明文导出单独授权，写向用户明确选择的位置，不作为自动恢复中间文件。

# 14. OVB1 开放加密交换格式

## 14.1 格式定位

**OVB1 是 CredPivot 拟制定的开放格式，不是现有行业标准。** P0 交付平台无关的完整逻辑快照加密归档，用于备份、迁移和独立恢复。SQLCipher 是本地工作库，不要求未来 Android 或第三方工具直接打开原 Mac 的数据库文件。

首发仅实现 Snapshot；为未来 Delta/附件等预留对象类型与版本机制，不提前冻结同步因果图、网络发布顺序或目录布局。将来可以迁移格式，不承诺零升级成本。

## 14.2 单文件归档的逻辑组成

```text
backup.ovb
  versioned envelope       # magic、版本、算法、受限长度等
  portable key slots       # 主密码槽、恢复槽；无设备快捷解锁包装
  authenticated manifest  # 备份 ID、范围、对象引用与完整性信息
  encrypted snapshot      # 完整业务逻辑状态
```

这是逻辑组成，不指定 ZIP、文件偏移或最终字节布局。M1 必须固定完整信封、清单认证、字段边界和解码规则。归档自包含，不依赖旁边的 `vault.json`、原 SQLCipher 文件、Keychain、App 账户或云服务。公开头只保留解锁和受限解析所需信息；用户名、域名、标题、业务 ID 和内容清单留在认证保护的密文中。

## 14.3 Snapshot 范围与生成

从同一一致性事务视图取得 Item、Credential、关系、当前密码、保留历史、待启用候选、回收站、业务策略和必要导入映射，以及逻辑数据版本。恢复后重建索引；本地路径、系统包装、UI 状态和网络凭据不进入快照。

P0 Snapshot 不含设备水位、同步队列、远端配置链或虚构的全局最新标记。备份生成须协调配置与数据视图，避免并发改密/安全重建混用不同 Vault 或密钥代际。后续同步快照可以复用记录编码，但须新增明确的同步版本和因果覆盖信息，不能把任意旧备份当作远端最新状态。

## 14.4 编码与认证规则

沿用 RFC 8785 JCS 规范化 JSON 作为逻辑对象编码；协议整数限制在精确安全范围，时间为 UTC Unix 毫秒，名称带 `_ms`，二进制采用无填充 Base64url。拒绝重复键、无效 Unicode 和浮点业务数值，不隐式归一化密码。[R20]

信封固定 magic、版本、Vault ID、对象类型、随机对象 ID、算法、nonce、长度及认证标签；关键头字段作为 AAD 绑定。每个对象只封装一次，内容变化使用新对象 ID/子密钥/nonce；重复写出可复用同一已封装字节。实际 HKDF 输入、AAD 编码、MAC 覆盖与对象清单绑定须形成字节规范和测试向量。

解密前限制文件、头、对象数量、嵌套和 KDF 资源，认证通过后才采用业务内容。未知算法、版本不兼容、缺少对象、长度不符或认证失败必须明确拒绝，不跳过坏对象伪造成功。

## 14.5 版本与跨平台升级

数据库 Schema、逻辑 Snapshot、加密信封分别标版本。未知关键类型不允许局部写回；可忽略扩展需原样保留，否则只读。新版本需要明确旧归档读取与迁移路径，失败保留原文件。P0 公开字节规范、稳定测试向量及独立恢复入口；共享 Rust 实现不替代跨实现解码验证。

## 14.6 独立恢复最低输入

完整 `.ovb` 文件 + 主密码或恢复密钥即可恢复声明范围；缺少任一必要对象则默认中止，不输出未经认证的残缺保险库。恢复到独立空目录，安装身份重新生成，不继承设备包装。是否切换日常使用由用户在校验后明确选择。

# 15. 后续同步设计边界与启用迁移

**本章全部为后续约束，不是 P0 实现或发布门禁。当前不运行同步引擎、不保存同步 Outbox、不累计无限操作日志。**

## 15.1 现在必须保留的边界

稳定业务 ID、内容修订、明确删除语义、统一 Core 事务和完整 Snapshot 是后续同步的基础。业务数据与设备数据、派生索引分开；不能把读取行为当作内容变更。后续同步使用逻辑对象，不直接双向同步 SQLCipher 或 WAL 文件。

## 15.2 单机转同步的迁移路径

1. 升级前生成并验证独立归档；由用户明确选择建立新同步空间或加入已有空间，不能覆盖未知远端。
2. 建立新空间时暂停写入，固定当前完整快照为基线，保留业务 ID，生成新的同步代际与设备身份。单机时代已永久删除的记录无需重放，当前回收站须包含在基线中。
3. 迁移事务建立同步状态和变更记录起点；此后每次业务修改与同步操作在同一事务提交。网络发布可稍后完成，但不能在抓取基线与开始跟踪之间丢失修改。
4. 初始发布可恢复、幂等，完成校验后才允许其他设备加入；后续编辑进入待发布队列。失败保留本地业务数据和明确状态，不凭上传请求发出就显示完成。
5. 加入已有同步空间须走明确接入流程；有独立本地内容时先备份并预览合并/迁入，不将两个同源但分别编辑的副本自动视作同一设备。

Vault ID 与同步代际分开；恢复副本可携带原 Vault 身份用于解密和来源识别，但不因此获得续写旧设备链的身份。P0 不需要生成未来设备链，后续首次接入时再分配。

## 15.3 合并与状态原则

不同独立记录可自动合并；同一记录并发编辑保留完整候选，不按墙上时间选胜者，不自动拼接密码/TOTP/私钥。同步要定义因果版本、删除与编辑冲突、父依赖、幂等、重放和快照覆盖，不能仅靠 P0 当前 revision_id 判定因果。

区分本地已保存、已发布、下载完成、已解密应用及有冲突。锁定时最多处理已封装密文，不能冒充已应用业务状态；不能证明被服务端隐藏的未知尾部不存在。乱序、重复、缺口和恢复后的新身份均须验证。

## 15.4 控制配置与安全边界

主密码槽更新、设备接入/撤销、安全重建、旧备份回滚和同步源迁移须另行设计并验证。共享 VMK 的成员具有完整 Vault 能力，不提供恶意成员隔离。主密码包装槽不能按普通业务冲突合并；未提交候选不应预先作为可解密对象公开上传，逻辑作废不能收回已暴露的解密能力。

远端并发提交、上传超时确认和本机状态推进需要明确原子边界。未经验证，不把 CAS、目录列举或文件锁假定为所有 WebDAV 服务均可靠支持的能力。

# 16. 后续 WebDAV 与坚果云验证

**本章为同步阶段准备。P0 不实现 WebDAV 客户端、账户配置、请求轮询或通用云存储框架。**

## 16.1 首个验证对象

用户计划使用坚果云 WebDAV。其官方帮助列有请求频率及单次列举数量限制，具体限制与行为须在实施时用当前账户确认；目前未连接用户服务，也未验证兼容。[R23]

## 16.2 必须完成的服务探测

- 应用密码认证、条件创建、ETag/If-Match 并发覆盖；两个基于同版本的写入是否至多一个成功。
- 超过单次列举上限的完整发现、分页及目录变化，不将截断结果当成完整远端。
- 上传成功但响应丢失、重复请求、断网重试、错误限流、大小/路径限制和取消。
- 多设备共用账户及其他应用竞争下的请求预算；前台触发、短时合并、空闲低频检查、退避重试。
- 大批量首次迁入采用完整基线或有限批次，避免每条记录引发多次独立网络请求。

服务行为不满足选定协议时先调整方案或明确兼容边界，不能静默退回无条件覆盖。坚果云仅是首个验证对象，不把其私有分页、路径或账户限制写入通用 OVB 加密格式。

## 16.3 最小适配边界

真正接入时再实现读、列举、不可变写、条件发布及错误分类等已验证能力。适配器只收到密文和必要元数据，不接触主密码、VMK 或业务明文。网络凭据作为设备本地秘密，不进入业务快照，并避免恢复保险库必须先从保险库取网络凭据的循环依赖。

Git 仍只作为后续单向归档备份候选；Android 的后台生命周期、其他 Provider、同步源迁移及远端垃圾回收分别验证，不为它们提前搭建通用框架。

# 17. 加密备份与灾难恢复

## 17.1 首发备份范围

P0 在 Mac 生成单文件 `.ovb` 完整归档，包含第 14 章定义的全部逻辑状态；提供 GUI 恢复及 Mac 独立 CLI。归档采用一致性视图，先写新临时目标并校验，再发布；不覆盖唯一可用备份。目标不保证原子替换时使用新文件名，未完成文件不得标记成功。

工作目录内恢复点只防部分误操作，不能防设备损坏或丢失。支持用户手动导出到独立本地位置或外置存储；本应用不执行网络上传。用户自行搬运已完成归档属于文件备份，不是双向同步，不允许通过云盘直接同步活动工作库。

## 17.2 自动本地恢复点

P0 默认启用：解锁期间业务数据有变化，且尚无定时恢复点或距上次超过 24 小时，则创建一份完整加密恢复点；不依赖 App 退出回调。批量导入、Schema 升级、目录迁移、主密码更新及安全重建前另行创建恢复点。高风险操作的前置备份失败则停止该操作，不阻止普通单条业务保存。

默认保留最近 10 份成功的本地恢复点，可调整；仅在新点验证成功后裁剪旧点，不删除唯一可用点、正在恢复的点或正在进行的操作所需回退点。记录磁盘占用，磁盘满或备份失败明确提示；与业务写入串行协调，不以后台备份失败伪造业务保存失败。自动恢复点使用现有解锁会话封装，不长期保存主密码。

## 17.3 恢复与副本语义

恢复先在独立空目录校验并生成完整工作库，核对通过后由用户选择切换；不自动覆盖当前工作库，不合并分别编辑过的两个副本。重新生成本机安装身份并重新绑定 Touch ID，不恢复旧设备包装或未来的同步设备身份。

当前可恢复的业务状态是快照所声明的范围，不代表快照之后的修改。保留来源 Vault ID 用于解密/来源识别不等于可以自动接入原同步空间。后续同步上线后，归档恢复和加入已有同步空间必须为不同流程。

P0 不提供任意逐条备份合并器；用户只需取回个别内容时可在独立恢复库中查看，之后显式复制到工作库。整库恢复、安全重建与 Bitwarden 迁入各有不同语义，不混用入口。

## 17.4 验证状态与历史风险

备份分别标记“已生成”“结构/认证已校验”“已用主密码验证恢复”“已用恢复密钥验证恢复”，附备份 ID、时间和范围。以已有 VMK 校验不等于两个解锁入口均已验证；后两项需要用户实际输入对应凭据，完成隔离恢复。

删除记录、裁剪历史或修改主密码不撤销旧归档/恢复点中的秘密；旧密码仍可能通过旧包装槽解出同一 VMK。安全重建产生新密钥和归档，但不能收回旧副本，实际服务凭据需按泄露范围轮换。

## 17.5 Git 与自动外部备份（后续）

Git 仅作为单向加密归档备份，不承担密码历史或业务合并，不自动 force push；首次认证不能依赖待恢复 Vault 内的唯一凭据。[R16] 外部定时备份、Git 调度与网络备份均不计入 P0；首发自动机制仅为上述本地恢复点。

# 18. 安全威胁模型与隐私设计

## 18.1 信任边界

P0 防护本地磁盘被复制、浏览器恶意网页与内容脚本、本机其他进程滥用 Agent、设备丢失、恶意导入和历史归档泄露/篡改。云服务回滚、网络同步攻击和恶意成员属于后续同步阶段，不能据此扩大首发网络实现。

不宣称完全解决：操作系统内核已被攻击者控制、攻击者长期监控解锁设备、用户输入低熵主密码、攻击者已读取运行中的明文内存等场景。产品必须公开威胁模型边界，而非使用“绝对安全”用语。

## 18.2 威胁与措施

| 威胁 | 主要防护 | 剩余风险 / 用户提示 |
|:--|:--|:--|
| Vault 数据目录泄露 | SQLCipher + 密钥包装 + 高成本 KDF | 弱主密码仍有离线猜测风险 |
| 归档被第三方取得 | OVB 认证加密、隐藏业务字段 | 文件大小、外部时间可能泄露 |
| 归档篡改/替换 | AEAD、认证清单、隔离恢复 | 有效旧归档仍可能被回放，离线文件不能自证为最新 |
| 恶意网页钓鱼 | Origin 匹配、默认用户确认、iframe 限制 | 用户主动向恶意站点提供密码仍可能泄露 |
| 恶意浏览器请求 | Native Host 身份验证、IPC ACL、操作级授权 | 被攻陷的授权扩展仍有风险 |
| 恶意导入文件 | 字节上限、递归/深度上限、严格解析、隔离恢复 | 解析库漏洞需要持续维护 |
| SSH Agent 滥用 | 每密钥策略、源进程/会话最小化、明确授权 | 通用 SSH 协议不能可靠识别全部最终主机 |
| 设备丢失 | 系统密钥库、生物识别、锁定策略 | 旧设备曾得到的 VMK 须通过完整轮换撤销 |
| 旧备份泄露 | 定期验证、VMK 安全重建、服务凭据轮换 | 不能远程擦除所有第三方副本 |
| 明文日志/崩溃转储 | 敏感字段脱敏、最小日志、禁采集默认 | 平台级转储可能含解锁时数据 |
| 剪贴板暴露 | 自动清理、最小驻留、提示高风险操作 | OS 剪贴板历史不可统一强制清除 |

## 18.3 登录与暴力攻击策略

不提供厂商在线账户时，可以减少传统账号撞库入口，但密码重用依然危及用户在第三方网站的账号。CredPivot 不应将“能防在线撞库”混同为“离线 Vault 绝对不可暴力破解”。主密码创建时优先倡导足够长的随机词组或随机高熵字符串，支持用户可理解的强度提示；不以无意义的字符类别规则代替熵。

## 18.4 密钥、会话与全局锁定

数据库密钥不得进入日志、诊断包、通知、扩展持久化存储或 Dart 全局状态。Mac Agent 持有本机唯一有效解锁会话；系统生物识别只能授权本机受保护包装，失败或包装失效时回退主密码。

默认锁定规则：主动锁定、系统锁屏、Mac 睡眠立即失效；Mac 无用户活动 5 分钟后锁定（可调整）。主窗口关闭默认不终止 Agent，仍受上述锁定规则约束。生命周期事件及 Touch ID 授权弹窗在 M0 真机验证。

锁定先递增会话代号、拒绝新秘密请求、取消等待中的填充/SSH 授权；返回秘密或签名结果前再次校验。关闭数据库连接、清理可控密钥内存；已提交记录不回滚，备份中断不发布残缺文件。P0 没有锁定后继续网络上传的任务。

生物识别变化、设备重启、应用重装或 Keychain 项失效时不得无认证降级。显式恢复重新生成本机身份和快捷解锁包装；不承诺能可靠识别操作系统层面的所有磁盘克隆。未来同步启用时强制创建新的设备身份，避免复用克隆状态。

锁定不能清除已释放到网页、SSH 客户端、系统剪贴板或 OS 内存副本中的数据。剪贴板默认 30 秒清理且只在内容仍是本应用最近写入值时清理，避免删掉用户后来复制的内容；不承诺清除第三方历史。

## 18.5 密码库历史删除语义

已解决的旧密码历史超过配置的 N 条时，当前逻辑数据库按 5.3 的稳定规则裁剪；未解决候选不计入该上限。已经生成的加密快照、Git 历史、离线副本及操作系统快照仍可能拥有较早的密文。如果用户需要让已泄露的密码失效，必须在对应网站轮换密码；如 VMK 或恢复密钥被暴露，必须执行 Vault 安全重建。

## 18.6 依赖、发布与供应链安全

固定加密依赖版本、开展 SBOM 清单、签名发布包、验证更新来源；依赖库与 SQLCipher 编译配置需要 CI 复现。禁止在生产构建中引入调试密钥、关闭 TLS 验证或自动上报 Vault 内秘密。重大密码学与同步协议改动需要双人审查和回归测试。

## 19.2 健壮性

- 本地写入遵循 SQLite 事务；进程崩溃、异常断电、网络中断后可进行一致性恢复。
- 重复导入、重复确认候选及恢复重试不重复产生业务副作用；同步幂等留待后续阶段。
- Snapshot 与当前配置只有在认证校验成功后才能交给业务使用；AEAD 解密产生的未认证输出不得提前流入解析/数据库。
- 数据库升级失败不覆盖原有可用副本；客户端向后兼容策略须明确。
- 不允许静默覆盖冲突密码、TOTP 种子和 SSH 私钥。

## 19.3 可观测与隐私

默认禁用内容级遥测。可记录非敏感的错误码、延迟、归档格式版本和备份状态；任何日志不包含明文用户名、密码、URL、TOTP 种子、SSH 私钥或整个 RPC 请求载荷。向用户导出的诊断包必须提供预览与自动脱敏。

## 19.4 国际化和可访问性

首发支持中文简体与英文，UI 文案采用统一键值管理；日期、时间、数字、中文字体/字符宽度符合系统区域设置。对视障用户，复制密码和 OTP 按钮提供易理解的语义，不能将明文秘密无意念出；Mac 大字体与窗口缩放不应裁切安全确认内容。

此例仅说明未来可能的原子变更结构，不要求 P0 存储这些字段或完整父版本图；正式格式在同步阶段重新设计。未来整个结构须经过 OVB 认证加密；record 是逻辑明文示意，不表示内层每个字段再次独立加密。mutations 包含该原子操作涉及的全部对象；任一依赖缺失整体等待。`timestamp_ms` 仅用于显示和审计，不决定并发胜负。正式协议明确完整状态结构和哈希输入，不直接使用占位字符串。

这些页面字段由受信任扩展后台从浏览器 API 获取，不接受网页自报值。Host 校验扩展连接、配对与操作权限，但不能仅凭这些字段独立证明网页身份。建议请求只返回必要候选元数据；实际取秘密需选中凭据并绑定一次授权，填充前后台再次核验 document/Origin。普通内容脚本无 `vault.export_all_secrets` 或全库枚举权限。

## A.5 SQLCipher 表结构示意

```sql
CREATE TABLE credentials (
    id TEXT PRIMARY KEY,
    item_id TEXT NOT NULL,
    kind TEXT NOT NULL,
    payload BLOB NOT NULL,
    current_revision TEXT NOT NULL,
    created_at_ms INTEGER NOT NULL,
    updated_at_ms INTEGER NOT NULL
);

CREATE TABLE password_history (
    id TEXT PRIMARY KEY,
    credential_id TEXT NOT NULL,
    secret BLOB NOT NULL,
    generated_at_ms INTEGER,
    activated_at_ms INTEGER,
    retired_at_ms INTEGER,
    FOREIGN KEY (credential_id) REFERENCES credentials(id)
);

CREATE TABLE import_mappings (
    source_namespace TEXT NOT NULL,
    source_item_id TEXT NOT NULL,
    local_item_id TEXT NOT NULL,
    source_digest BLOB NOT NULL,
    PRIMARY KEY (source_namespace, source_item_id),
    FOREIGN KEY (local_item_id) REFERENCES items(id)
);
```

上述 DDL 仅示意部分表，`items`、候选及关系表等未完整展开；正式 Schema 需定义主外键、枚举、修订和迁移规则。`current_revision` 是 P0 当前内容修订，不能在未来被直接当作完整因果信息；`active_password_revision` 属于密码启用状态，与内容修订分开。`payload/secret/source_digest` 均在 SQLCipher 内，不因 BLOB 类型就声称字段独立加密。P0 无 `sync_outbox` 等同步表。
