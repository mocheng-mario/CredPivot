# 凭据关联方案

实现凭据模块的关联、匹配、连接、删除和迁移时，以本文为准。更早的对话说法或现有代码与本文冲突时，以本文为准。

本文里的「账户」就是现有的账密记录。不额外增加账户容器，也不为独立凭据创建默认账户。

## 1. 模块与数据归属

| 模块 | 保存内容 | 能否单独存在 | 与其他模块的关系 |
|---|---|---|---|
| 账户 | 用户名、当前密码、密码候选、密码历史、网站规则、备注、自定义字段 | 能 | 可关联多个 MFA、SSH 密钥、通行密钥 |
| MFA | 种子、算法、位数、周期、自身 origin 规则、一组恢复码 | 能 | 最多关联一个账户 |
| SSH 密钥 | 密钥材料、指纹、自身目标匹配规则、使用策略 | 能 | 可关联多个账户 |
| 通行密钥 | 通行密钥材料、自身身份与匹配信息 | 能 | 最多关联一个账户 |
| 服务器连接 | 目标地址、端口、账密来源、所选 MFA、所选 SSH 密钥 | 能 | 独立配置，或引用一个账户 |
| 安全笔记 | 敏感文本、自定义信息 | 能 | 只建立普通查看链接，不参与认证 |
| 回收站 | 已删除记录及恢复所需信息 | — | 统一处理恢复和永久删除 |

账户的当前密码可以为空。空密码仍然是一条账户。

恢复码记录可以不挂任何 MFA 而单独存在，但当前不设恢复码模块，模块列表里不展示。录入、查看、待挂和标记使用都只出现在 MFA 里。一条 MFA 最多使用一组；这一组里有多条码，每条码有自己的使用状态。勾选删除正在使用这组恢复码的 MFA 时，整组一起进入回收站。没被删除的 MFA，恢复码留在该 MFA 上。尚未挂到 MFA 的恢复码不随账户删除。当前保险库没有恢复码记录，实现时不用迁移旧恢复码。

密码候选和密码历史是账户的内部数据，不作为独立凭据参与关联。

从账户详情、独立模块或服务器连接进入同一条 MFA、SSH 密钥或通行密钥时，查看和编辑的都是原记录。关联不复制秘密，也不把账户的网站规则复制到 MFA、密钥或通行密钥上。

MFA 或通行密钥已经关联其他账户时，改挂到新账户必须明确执行「更换关联账户」，不能悄悄覆盖原关系。

## 2. 关联数量

| 关联 | 数量 |
|---|---|
| 账户 → MFA | 0 到多个 |
| MFA → 账户 | 0 或 1 个 |
| 账户 ↔ SSH 密钥 | 多对多 |
| 账户 → 通行密钥 | 0 到多个 |
| 通行密钥 → 账户 | 0 或 1 个 |
| 服务器连接 → 账户 | 独立模式为空；关联模式为 1 个 |
| 服务器连接 → MFA | 0 或 1 个 |
| 服务器连接 → SSH 密钥 | 0 或 1 个 |

一条账户挂多条 MFA，是因为这一套账户会用于多个网站，每个网站有自己的 MFA。

MFA、SSH 密钥、通行密钥没有关联账户时，也可以独立保存和使用。

有效认证关联只存在于同一分区内。浏览器匹配、Git / SSH 自动匹配、可用连接取用认证材料，都只看当前分区里的有效关联。停用连接上保留的旧引用不属于有效认证关联，可以悬空或跨分区，规则见第 5 节。

## 3. 账户详情与各模块入口

账户详情聚合展示，各模块仍保留自己的管理入口。

账户详情展示：

- 账户基本信息
- 当前密码、候选与历史
- 网站规则
- 关联 MFA：验证码、剩余时间、恢复码状态；可以添加、关联、解除关联。是否启用 MFA 由关联自动决定，不提供手选
- 关联 SSH 密钥：名称、指纹；可以添加、关联、解除关联
- 关联通行密钥：名称、所属网站；可以查看、关联、解除关联
- 引用此账户的服务器连接：可用状态、失效原因
- 备注与自定义字段

在账户下可以直接创建并关联 MFA、SSH 密钥，也可以选择已有记录。创建完成后，它们仍是独立凭据。

各独立模块显示关联账户及使用方，并可以跳转。恢复码只在 MFA 管理里录入和查看。安全中心可以展示统计和跳转，不另存一套数据，也不再放「网站恢复码」面板。

### 3.1 启用状态与恢复码展示

账户是否启用 MFA，由有没有关联 MFA 决定，不再让用户在「未知 / 已启用 / 未启用」里选择。

- 至少有一条关联 MFA：状态为已启用。
- 没有关联 MFA：状态为未启用。
- 加上第一条或解除最后一条时，状态立刻跟着变。安全报告读这个结果，不另存一份手选值。

通行密钥的网站开关已经在浏览器插件里。插件弹窗对当前 HTTPS 网站显示「此网站已启用」或「未启用」，并可以「在此网站启用 / 在此网站停用」。这个开关按网站 origin 存在本机浏览器里，不写入保险库。未启用时，该网站继续走浏览器原来的通行密钥；启用后，CredPivot 才接入这个网站的通行密钥创建和使用。

账户新关联一条通行密钥时，按这条通行密钥自己的站点标识，把对应网站的插件开关自动设为启用。用户可以之后在插件里手动关闭。手动关闭保持关闭，打开插件或账户仍关联着这条通行密钥时，都不会把它再自动打开。用户自己再次打开后才恢复启用。解除或删除通行密钥时，不自动改这个开关。

账户详情里，已关联通行密钥的网站显示插件开关是开还是关。关着的可以看出来是手动关闭。

安全中心里的「网站恢复码」面板去掉，包括那里的列表和新增。恢复码只从 MFA 查看和录入。

MFA 详情展示这组恢复码的状态，不跳到单独模块：

- 没有恢复码：显示未录入，并可以在这里录入。
- 已有恢复码：显示剩余条数和总条数，并可以进入查看、标记已使用。

## 4. 浏览器与自动匹配

匹配范围限于当前分区。当前网页登录流程里选中的账户，只作用于这一次流程，不用 App 最后打开的账户。

没有匹配结果时，显示没有可用项，不扩大到全局候选。有多个结果时，由用户选择，不默认取第一项。

### 4.1 账户

要填写密码时，用当前域名匹配账户的网站规则。密码为空的账户也能命中。没有命中，提示没有可用的身份。

### 4.2 MFA

MFA 的网站 origin 只约束浏览器填充。

| 当前登录流程 | MFA 候选 |
|---|---|
| 未选择账户 | 还没挂任何账户，且自身 origin 命中的 MFA |
| 已选择账户 A | 关联着 A 的 MFA；写了 origin 的必须命中当前网站；没写 origin 的保留在候选里 |

没写 origin 的 MFA 可以在 App 内使用。未选择账户时，它不参与浏览器匹配。

用户直接打开验证码页，或已经在页面上手动输入密码时，上面的候选规则不变，也不自动选中账户。验证码页另外提供账户选择：

- 网站规则命中当前页的账户
- 名下有 MFA，且该 MFA 的 origin 命中当前页的账户
- 两类都不命中时，可以手动选择一个账户

选定账户 A 之后，MFA 候选改为上表「已选择账户 A」那一行。

服务器连接不拿 MFA 的 HTTPS origin 去和 SSH 主机比较。连接用哪条 MFA，只看配置里的显式选择。

### 4.3 通行密钥

通行密钥不看账户的网站 origin，也不看当前有没有选中账户。

浏览器只按通行密钥自己的规则匹配：站点标识，以及这次 WebAuthn 请求。已经挂到某个账户上的通行密钥，只要自身规则命中，就进入候选。没挂账户的也同样。挂接只用于账户详情里的展示和跳转。

自身规则不命中的通行密钥，不会因为账户的网站规则里写了同一个网站就变成可用。

### 4.4 SSH 密钥

SSH 密钥的目标匹配规则只用于没有指定密钥时的自动匹配，不使用网站 origin。已关联账户不阻止它按自身规则被 Git / SSH 自动匹配使用。自动匹配到多把密钥时，由用户选择，不默认第一把。

服务器连接里已经显式选中的密钥不受目标匹配规则限制。规则后来不再覆盖这台服务器时，这条连接继续使用这把密钥，也不因此停用。

## 5. 服务器连接

连接是独立能力。host、port、user、pass 都必须有值。一条连接只使用配置里明确选择的认证材料，不自动更换账户、MFA 或 SSH 密钥。

账密来源严格二选一：

| 配置项 | 独立配置 | 关联账户 |
|---|---|---|
| 用户名、密码 | 由连接自身保存 | 从所选账户直接读取，不保存副本 |
| MFA 候选 | 本分区可用的 MFA，包括已经挂在某个账户上的 | 仅该账户关联的 MFA |
| SSH 密钥候选 | 本分区可用的 SSH 密钥，包括已经挂在某个账户上的 | 仅该账户关联的 SSH 密钥 |
| MFA、SSH 是否必选 | 都可以不选 | 都可以不选 |
| 保存内容 | 自有用户名、密码，以及凭据引用 | 只保存账户及凭据引用 |

独立模式选中了已经关联账户的 MFA 或 SSH 密钥时，提示用户可以改为关联对应账户。只提示，不阻塞。SSH 密钥关联了多个账户时，提示列出这些账户，不替用户指定唯一一个。

选择关联账户后，不默认勾上第一项 MFA 或 SSH 密钥，也不自动继承账户上其他未选择的凭据。用户要使用哪一条，必须明确选择；也可以都不选。

更换关联账户时，重新校验已有选择。不属于新账户的 MFA、SSH 密钥必须清除，由用户重新选择。

保存后只保留当前模式的数据。切换到关联模式时，不留下隐藏的自有用户名和密码。切换到独立模式时，不自动复制关联账户的密码；用户需要自己填写用户名和密码。

关联模式保存时，如果从账户读到的当前密码为空，连接不能保存。host、port、user、pass 任一不能得到有效值时，同样不能保存。

相同 host 加同一条账户时，提示可能重复，仍然允许保存。

账户侧发生解除关联、普通删除，或连接所依赖的关系不再成立时，连接只改为停用，不改写它已经保存的账户、MFA、SSH 密钥引用，也不把账户的用户名和密码抄进连接。这些旧引用可以在停用的连接里查看，包括目标已经不存在，或目标已在其他分区。它们不是有效认证关联，不参与同分区校验，不能用来发起连接或取用认证材料。

用户之后进入重新配置并保存，才按新选择写入。这次写入的账户、MFA、SSH 密钥必须仍然存在，并且和这条连接处于同一分区。跨分区的旧引用不能保存成新的有效关联。目标已不存在时，必须改选仍然有效、且同分区的对象。

## 6. 连接停用

停用只针对会影响这条连接实际认证的关系或依赖失效。连接停用后，禁止通过它发起连接或取用认证材料。界面展示具体原因。

停用后，即使用户把源数据改回原值，或把凭据从回收站恢复，也不自动重新启用。用户进入重新配置，核对账密来源、MFA、SSH 密钥，校验并通过保存后，连接才恢复可用。这次保存就是重新确认，不必为了能保存而修改一个无意义字段。保存时的分区和引用有效性按第 5 节执行。

重新配置时的保存要按当前模式重新校验。关联模式此时读到的密码仍为空，则不能保存，连接继续停用，直到账户有了密码，或用户改成独立模式并填写自己的用户名和密码。

| 变化 | 是否停用相关连接 |
|---|---|
| 关联账户的当前密码改变 | 否。连接保持可用，之后直接读到新值。已经保存的连接，事后把密码改成空，仍然可用，并使用这个空密码 |
| 关联账户的用户名改成另一个非空值 | 否。连接保持可用，之后直接读到新用户名。只影响关联模式；独立模式用连接自己保存的用户名 |
| 关联账户的用户名变成空或只有空白 | 是。连接停用。重新配置时 user 仍必填，无效则不能保存 |
| 所选 MFA 的种子、算法、位数、周期改变 | 否 |
| 所选 SSH 密钥的使用规则改变 | 否 |
| 账户新增了其他未被该连接选择的 MFA、SSH 密钥 | 否 |
| 创建密码候选、查看历史，当前密码未改变 | 否 |
| MFA 恢复码内容或使用状态变化 | 否 |
| 名称、备注、收藏、分组等展示信息变化 | 否 |
| 关联模式的连接所引用的账户被解除、删除，或不再可用 | 是 |
| 关联模式下，所选 MFA 或 SSH 密钥被该账户解除关联，或改挂到别的账户 | 是 |
| 所选 MFA 或 SSH 密钥被删除，或变成不可用 | 是 |
| 依赖迁出当前分区，导致和连接不再处于同一分区 | 是 |

独立模式的连接只受自己实际引用的那条 MFA 或 SSH 密钥影响。这条凭据还在、并且仍在同一分区时，不因为它和某个账户的挂接变化而停用，也不因为其他账户的关联调整而停用。

## 7. 删除、回收站与恢复

删除先进入回收站。永久删除在回收站里处理。

| 操作入口 | 普通删除 | 删除账户及勾选的关联内容 |
|---|---|---|
| 单个账户的操作菜单 | 支持 | 支持 |
| 批量删除账户 | 支持 | 不支持 |
| MFA、SSH 密钥、通行密钥、连接等其他模块 | 支持 | 不支持 |

普通删除账户时，账户自身以及它的密码、候选、历史进入回收站。关联的 MFA、SSH 密钥、通行密钥保留，只解除和这个账户的关联。引用该账户的连接按第 6 节停用，连接里的引用保持原样。

「删除账户及勾选的关联内容」始终删除当前账户。同时列出它直接关联的 MFA、SSH 密钥、通行密钥，由用户勾选哪些一起删除。没勾的只解除关联，记录留下。

勾选了仍被其他账户使用的 SSH 密钥时，提示那些账户也在用，不阻塞。确认后该密钥进入回收站，其他账户上的挂接消失。选中了被删 MFA 或 SSH 密钥的连接停用。不沿关联网络递归删除其他账户或服务器连接。

被勾选删除的 MFA，其整组恢复码一起进入回收站。没被勾选的 MFA，恢复码留在该 MFA 上。

单独删除一条 MFA 时，删除这条 MFA，并把它正在使用的那组恢复码一起放入回收站。单独删除一条 SSH 密钥、通行密钥或连接时，只删除这条记录并解除它自己的挂接。因此失效的连接停用。

恢复记录时，先恢复记录本身，再恢复仍然合法的挂接：

- 对方记录已经不存在时，不恢复这条挂接。
- MFA 或通行密钥已经关联了另一个账户时，保留新的关联，不覆盖。
- 恢复不会自动重新启用已经停用的连接。相关连接仍要重新配置并保存。

## 8. 分区迁移

迁移前预览依赖，并提示哪些记录还被其他账户或连接使用。用户勾选要一起迁移的记录。强行迁移时，只迁移勾中的记录，不沿关联网络把没勾的账户或连接一起带走。

没勾的留在原分区。为了保持同分区才能认证关联，迁走之后这些跨分区关系要断开：

- 一把 SSH 密钥被迁走，而仍关联它的账户留在原分区：断开这些挂接。留在原分区、并且选中了这把密钥的连接停用。
- SSH 密钥留下，而账户被迁走：断开这把密钥和该账户的挂接。
- MFA 或通行密钥只属于被迁走的账户、且用户把它留下：解除和该账户的挂接，记录留在原分区。
- 连接留下，但它引用的账户、MFA 或 SSH 密钥已经被迁走：连接停用，旧引用保留给查看和重新配置，不删除。
- 连接被勾走，但它依赖的账户、MFA 或 SSH 密钥没有一起勾走：连接停用，旧引用保留。重新保存时这些跨分区引用不能写成有效关联。

## 9. 分组与普通链接

分组只负责列表里的组织。一个分组可以容纳不同类型的记录。同一分组不表示这些记录已经认证关联。

资料里不再提供任意记录互相关联，也不再保留只用于跳转的普通链接。`related_item_ids` 不再写入，已有内容清空。

## 10. 主要操作

| 操作 | 流程 |
|---|---|
| 新建账户 | 填写账密和网站规则，保存。之后按需创建或关联 MFA、SSH 密钥、通行密钥 |
| 独立添加 MFA | 扫码或输入，设置自身信息及 origin，可选关联一个账户，可选录入这一组恢复码 |
| 在账户下添加 MFA | 创建，或选择一条尚未关联账户的 MFA，保存关联。账户详情和 MFA 模块看到的是同一条记录 |
| 添加 SSH 密钥 | 创建或导入，设置自身规则，可选关联一个或多个账户 |
| 创建通行密钥 | 完成网站注册流程，独立保存，可选关联一个账户 |
| 新建连接 | 填写目标，选择独立或关联模式，按该模式的候选选择 MFA 和 SSH 密钥，校验后保存 |
| 修改当前密码 | 更新账户当前密码。引用它的连接保持可用，之后读取新密码 |
| 解除 MFA、密钥或通行密钥和账户的关联 | 保留这条独立凭据，更新两边的展示。关联模式连接若选中的就是它，连接停用 |
| 删除账户 | 选择普通删除，或删除账户并勾选关联内容。预览范围和影响，确认后进入回收站 |
| 恢复记录 | 恢复内容，按第 7 节校验挂接。受影响的连接仍需重新配置 |

## 11. 实现对照

对照实现时，下面这些当前做法不要延续：

- 不要用 `login_credentials.linked_totp_id` 这种单值字段表示 MFA。一条账户可以有多条 MFA。
- 不要用 `details.related_item_ids`，也不要在资料里提供任意记录互相关联。认证关联只使用本文的账户、MFA、SSH 密钥、通行密钥和服务器连接关系。
- 不要让服务器连接在未显式选择时，回退到账户上的某一条 MFA 或 SSH 密钥。
- 恢复码可以不挂 MFA 而存在，但不要做成导航里的独立模块。展示和使用只放在 MFA 详情里。安全中心的「网站恢复码」面板去掉。当前库没有恢复码记录，不要为旧恢复码做迁移。
- 账户的 `mfa_state` 不再手选。有关联 MFA 就是已启用，没有就是未启用。
- 通行密钥的网站开关继续留在插件本机的 `passkey_enabled_sites`。新关联通行密钥时按站点标识自动打开；用户手动关闭后保持关闭。
- 通行密钥的浏览器匹配不要先要求命中账户网站规则。
- 分组不要再按模块拆成互相看不见的 scope 来表示「这些是同一账户」。分组不等于认证关联。
