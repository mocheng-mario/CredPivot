## 2. [P1] 锁定仍未覆盖空闲锁通知和已经打开的秘密弹窗

性质：明确的状态传播和缓存失效缺口。

位置：[session_guard.rs:6](/Volumes/WorkSpace/zx/CredPivot/crates/agent/src/session_guard.rs:6)、[main.dart:59](/Volumes/WorkSpace/zx/CredPivot/apps/macos/lib/main.dart:59)、[credentials_page.dart:1024](/Volumes/WorkSpace/zx/CredPivot/apps/macos/lib/credentials_page.dart:1024)。

1. Rust 的空闲锁定清除了会话和 pending fills，但没有向 Swift/Dart 发布锁定事件。Dart 只接收 Swift 的 `onVaultLocked`，没有周期状态同步；请求得到 Locked 错误也只是抛异常。因此空闲锁后，页面仍可能保持旧的 unlocked 状态和恢复码列表。
2. 即使菜单栏锁定成功通知了 Dart，`_onVaultLockedExternally` 也只更新页面状态，没有关闭已经推入 Navigator 的秘密弹窗。恢复码弹窗提前复制了 `codes`，其显示及复制回调不再访问 Agent；清空原页面列表不影响这些副本。TOTP URI/二维码弹窗同样需要覆盖。

Flutter 的 `showDialog` 路由可在原调用 widget 被移除后继续存在，不能依靠隐藏底层页面关闭它：[官方文档](https://api.flutter.dev/flutter/material/showDialog.html)。

最小建议：所有锁定来源统一传播状态；锁定时关闭敏感路由并使在途秘密请求失效；复制回调核对当前会话代际。先修现有锁定通路，无需新建状态管理架构。

## 3. [P1] Schema 迁移和版本号未处于同一事务，中断后可能再也打不开旧库

性质：有具体失败窗口的数据可用性风险，未做故障注入。

位置：[migrate.rs:126](/Volumes/WorkSpace/zx/CredPivot/crates/core/src/migrate.rs:126)、[migrate.rs:229](/Volumes/WorkSpace/zx/CredPivot/crates/core/src/migrate.rs:229)、[local_db.rs:51](/Volumes/WorkSpace/zx/CredPivot/crates/core/src/local_db.rs:51)。

V6/V7 包含多个 `ALTER TABLE ... ADD COLUMN`，随后才单独更新 `user_version`。外层打开数据库也没有包事务。如果某列已加成功后进程退出，或后续语句失败，版本号仍旧；再次打开会重复 ADD COLUMN，报重复列并退出迁移。V8 的修复函数只补服务器表字段，无法绕过前面的 V6/V7 错误。

SQLite 未显式开启事务时，不会自动把这一整段迁移和版本更新组成原子操作：[事务文档](https://www.sqlite.org/lang_transaction.html)。

最小建议：每个版本的 DDL 与 `user_version` 更新放在同一事务中；针对已经可能产生的部分迁移状态，增加有限、明确的恢复处理。不要把所有错误都吞掉当作“已迁移”。

## 4. [P1] Bitwarden URI 规范化丢端口，改变浏览器凭据匹配边界

性质：明确的输入转换错误；是否误填取决于用户后续访问和操作。

位置：[bitwarden_import.rs:110](/Volumes/WorkSpace/zx/CredPivot/crates/core/src/bitwarden_import.rs:110)。

`normalize_login_origin` 对 authority 执行 `split(':').next()`，使 `https://example.com:8443/login` 变为 `https://example.com`。原站点的匹配失效，默认 HTTPS 端口的另一服务却可以匹配该凭据。IPv6 如 `https://[2001:db8::1]:8443/` 也会被截断成无效地址。无斜杠但含 query 的 URL 同样不是可靠的字符串切分输入。

最小建议：使用真正的 URL 解析与 origin 序列化，保留非默认端口和合法 IPv6；对不支持的 URI 显式报告，不能靠切冒号推导 origin。

## 5. [P1] 安全重建会删掉旧恢复点，目录切换也仍存在崩溃窗口

性质：恢复点删除是明确行为；激活中断是潜在故障风险。

位置：[vault_pipeline.rs:232](/Volumes/WorkSpace/zx/CredPivot/crates/core/src/vault_pipeline.rs:232)、[snapshot.rs:13](/Volumes/WorkSpace/zx/CredPivot/crates/core/src/snapshot.rs:13)、[vault_session.rs:648](/Volumes/WorkSpace/zx/CredPivot/crates/agent/src/vault_session.rs:648)。

重建前先生成恢复点，随后 clone 仅把 `vault.json` 和数据库放进 staging。激活时原目录改名为 backup，成功后 `remove_dir_all(backup)`，于是原目录的历史恢复点和刚创建的前置恢复点一起被删除。这与当前设计文档要求说明旧恢复点需用旧凭据打开的语义不一致。

另外，两次 rename 并非整个流程的单次原子切换。如果进程在“旧目录改名”后、“新目录接管原路径”前退出，活动路径不存在；启动只检查原路径，未见重建事务标记或自动恢复。旧数据通常还在随机 backup 路径，不能称为已经永久丢失，但普通启动不能自动恢复。回滚 rename 的错误也被忽略。

最小建议：保留可识别的旧目录/恢复点直至新库激活和用户确认，明确旧凭据要求及清理策略；为切换增加很小的持久化阶段记录和启动恢复逻辑，或使用可恢复的活动目录指针切换。不要无条件删除唯一的重建前历史。

## 7. [P2] 浏览器 documentId 实际是 URL，同 URL 刷新会复用授权上下文

## 10. [P2] shutdown 取消了监听任务，但已经接收的连接仍可继续执行

性质：具体生命周期缺口；触发需要停止/重启时存在已接受但未完成的连接。

位置：[runtime.rs:90](/Volumes/WorkSpace/zx/CredPivot/crates/agent/src/runtime.rs:90)、[ipc.rs:22](/Volumes/WorkSpace/zx/CredPivot/crates/agent/src/ipc.rs:22)、[ssh_agent.rs:17](/Volumes/WorkSpace/zx/CredPivot/crates/agent/src/ssh_agent.rs:17)、[lib.rs:72](/Volumes/WorkSpace/zx/CredPivot/crates/credpivot-ffi/src/lib.rs:72)。

顶层四个任务现在会 abort/join，退出锁库也已增加。但每条连接经 `tokio::spawn` 后没有保存 handle，也没有停止标记；FFI stop 保留了 Tokio runtime。已经通过 peer 校验、停在读取请求体的 IPC 连接可以在 shutdown 后继续处理请求。若其随后完成的是带正确密码的解锁请求，旧会话能再次挂载数据库，而其单写锁已经随 AgentRuntime 释放。

最小建议：管理连接任务，停止时取消并等待；停止标志在请求执行前核对。完成旧连接清理后再释放单写锁。
